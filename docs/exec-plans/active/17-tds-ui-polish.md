# 17. 전체 화면 UI 정리 및 TDS 스타일 적용

## 목적

MVP 전체 화면이 Apps in Toss 모바일 WebView 안에서 일관된 TDS 기준으로 보이고, 사용자가 각 화면에서 해야 할 행동을 바로 이해할 수 있게 한다.

이 작업은 새 기능을 추가하는 작업이 아니라, 1번부터 15번까지 구현된 화면의 문구, 레이아웃, 상태 표현, CTA 사용 방식을 정리하는 작업이다.

## 구현 범위

- 로그인, 오늘 문제 진입, 문제 없음, 오디오, 객관식, 제출, 전면형 광고, 결과, 포인트 지급, 보상형 광고, 완료, 중복 차단 화면을 점검한다.
- TDS 컴포넌트를 우선 사용하도록 버튼, 리스트, 상태 표시, 하단 CTA를 정리한다.
- 모바일 WebView safe area 기준으로 하단 CTA와 주요 콘텐츠가 겹치지 않게 한다.
- 화면별 주요 목적과 주요 CTA가 하나로 보이도록 정리한다.
- 로딩, 실패, 빈 상태, 미지원, 완료 차단 상태의 표현을 통일한다.
- 정답, 오답, 완료, 문제 없음, 보상 대기, 보상 실패 상태 문구를 구분한다.
- 긴 선택지, 긴 오류 문구, 보상 문구가 화면 밖으로 넘치지 않게 정리한다.
- 빠른 연속 탭 상황에서 버튼의 `loading`과 `disabled` 표현이 일관되게 보이도록 한다.

## 제외 범위

- 새 화면 또는 새 기능 추가
- 라우팅 구조 전면 개편
- 로그인, Firebase, Toss SDK, Toss Ads, 서버 API 계약 변경
- 보상 정책, 재도전 정책, 하루 1문제 정책 변경
- 통계, 학습 기록, 공유, 추천, 랭킹 기능
- 디자인 시스템 교체 또는 TDS와 무관한 외부 UI 도입
- completed 문서 작성

## 구현 기준

- `docs/design-docs/style-guidelines.md`의 TDS 우선 원칙을 따른다.
- TDS로 해결할 수 있는 버튼, 하단 CTA, 리스트, 상태 표시는 TDS 컴포넌트를 우선 사용한다.
- 주요 CTA는 TDS `Button` 또는 `BottomCTA` 계열을 우선 검토한다.
- 주요 CTA가 하나인 화면은 `display="full"` 또는 `BottomCTA.Single` 기준으로 정리한다.
- 두 개의 CTA가 필요한 화면은 주/보조 역할을 명확히 나누고 `BottomCTA.Double` 사용을 검토한다.
- 하단 고정 CTA는 safe area padding을 반영해 홈 인디케이터와 겹치지 않게 한다.
- `loading` 중인 CTA는 `disabled`도 함께 적용한다.
- 화면마다 상단에는 현재 상태나 핵심 맥락, 중앙에는 주요 콘텐츠, 하단에는 다음 행동을 둔다.
- 한 화면에 소개, 문제 풀이, 결과, 보상 설명을 동시에 넣지 않는다.
- 정답 상태와 포인트 지급 완료 상태를 같은 문구로 표현하지 않는다.
- 오답 상태와 재도전 가능 상태를 같은 문구로 표현하지 않는다.
- 오늘 문제 없음 상태와 오늘 학습 완료 상태를 같은 문구로 표현하지 않는다.
- 광고 미지원, 광고 실패, 포인트 지급 실패는 각각 다른 상태로 안내한다.
- 보상 문구는 기대 보상과 실제 지급 완료를 혼동하지 않게 쓴다.
- 커스텀 UI를 유지해야 하는 경우 TDS의 간격, 타이포그래피, 색상, 인터랙션 감각과 맞춘다.
- UI 정리 과정에서 API 응답 구조나 상태 전이 규칙을 바꾸지 않는다.

## 상태 및 예외 처리

- `loading`: 데이터를 불러오거나 요청을 처리 중인 상태다.
- `disabled`: 조건이 충족되지 않아 액션을 실행할 수 없는 상태다.
- `error`: 재시도 가능한 실패 상태다.
- `empty`: 오늘 문제 데이터가 없는 상태다.
- `unsupported`: Toss SDK, 광고, WebView 기능이 현재 환경에서 지원되지 않는 상태다.
- `completed_blocked`: 오늘 학습이 완료되어 현재 액션을 실행할 수 없는 상태다.
- 각 상태는 화면마다 같은 의미와 유사한 시각 표현을 가져야 한다.
- 오류 상태에서 사용자가 할 수 있는 다음 행동이 없으면 의미 없는 CTA를 제공하지 않는다.
- 하단 CTA가 콘텐츠를 가리지 않도록 본문 하단 여백을 확보한다.
- 긴 텍스트는 줄바꿈되고 부모 영역을 넘지 않아야 한다.
- 아이콘만 사용하는 버튼에는 접근성 라벨을 둔다.

## 완료 기준

- 모든 주요 화면이 TDS 우선 기준을 따른다.
- 화면별 주요 CTA와 보조 CTA의 역할이 명확하다.
- 로딩, 비활성화, 실패, 빈 상태, 미지원 상태가 일관되게 표현된다.
- 정답, 오답, 완료, 문제 없음, 보상 실패 상태가 문구와 시각적으로 혼동되지 않는다.
- 모바일 WebView에서 하단 CTA가 safe area와 겹치지 않는다.
- 긴 선택지와 긴 오류 문구가 UI 밖으로 넘치지 않는다.
- 빠른 연속 탭 상황에서도 CTA 상태가 중복 요청을 유도하지 않는다.
- 기능 동작과 API 계약이 1번부터 15번 범위를 벗어나지 않는다.
- 새 기능, 새 정책, 새 화면이 추가되지 않는다.

- 예외가 필요한 작업은 이 섹션에 예외 사유와 진행 방식을 명시한다.
- UI 정리 중 기능 로직이나 API 계약 변경이 필요하면 이번 작업에 포함하지 말고 별도 후속 작업으로 분리한다.
