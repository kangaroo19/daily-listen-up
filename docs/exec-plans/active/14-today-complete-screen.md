# 14. 오늘 학습 완료 화면 구현

## 목적

오늘 학습을 완료한 사용자가 더 이상 문제 풀이로 돌아가지 않고, 오늘의 학습 완료 상태를 명확히 확인할 수 있게 한다.

이 작업은 완료 사용자에게 보여줄 전용 화면을 구현하는 작업이며, 통계나 학습 기록 같은 확장 기능은 포함하지 않는다.

## 구현 범위

- 오늘 학습 완료 상태 사용자에게 완료 화면을 보여준다.
- 11번 포인트 지급 완료 또는 이미 지급됨 상태 이후 완료 화면으로 이동한다.
- 앱 재진입 시 이미 완료한 사용자를 완료 화면으로 바로 안내한다.
- `promotionStatus`, `isPromotionGranted`, `promotionGrantKey`를 기준으로 보상 상태를 짧게 표시한다.
- 지급 처리 중, 지급 실패, 지급 완료 상태를 완료 화면 안에서 구분한다.
- 오늘 문제 다시 풀기 CTA를 제공하지 않는다.
- 홈으로 돌아가기, 닫기, 새로고침처럼 완료 이후 가능한 최소 액션을 제공한다.
- 모바일 WebView safe area를 고려해 하단 CTA를 배치한다.

## 제외 범위

- 포인트 지급 요청 API 호출 구현
- 보상형 광고 재도전 구현
- 당일 중복 학습 가드 전체 구현
- 학습 통계, 연속 학습, 캘린더, 랭킹, 공유 기능
- 포인트 지갑, 상세 지급 내역, 고객센터 연결 고도화
- 내일 문제 미리보기, 추천 콘텐츠
- 완료 이후 추가 보상 이벤트
- completed 문서 작성

## 구현 기준

- 완료 화면은 `userKey + quizDate` 진행 상태가 `completed`이거나 `isPromotionGranted`가 `true`인 경우를 기준으로 한다.
- 서버가 `already_granted` 또는 이미 지급됨 상태를 반환한 경우에도 완료 화면으로 안내한다.
- 완료 화면은 오늘 문제를 다시 시작하는 CTA를 제공하지 않는다.
- 완료 상태와 포인트 지급 상태를 같은 문구로 뭉개지 않는다.
- `promotionStatus: granted`이면 지급 완료 상태를 표시한다.
- `promotionStatus: pending`이면 학습은 완료되었지만 지급 확인이 진행 중임을 짧게 표시한다.
- `promotionStatus: failed`이면 학습 완료와 지급 실패를 구분하고 재시도 또는 상태 확인 기준을 제공한다.
- `promotionGrantKey`가 있으면 화면 내부 로직에는 사용할 수 있지만 사용자에게 긴 key를 그대로 노출하지 않는다.
- 보상 금액은 실제 지급 완료와 기대 보상을 혼동하지 않게 표현한다.
- 화면 상단에는 오늘 학습 완료 상태를 명확히 표시한다.
- 화면 중앙에는 짧은 완료 안내와 보상 처리 상태를 둔다.
- 화면 하단에는 하나의 주요 CTA를 둔다.
- 주요 CTA는 TDS `Button`을 우선 사용하고 `display="full"` 기준으로 배치한다.
- 이미 완료한 사용자가 브라우저 뒤로 가기 또는 라우트 직접 접근으로 문제 풀이 화면에 진입하려 하면 완료 화면으로 돌려보내는 기준을 둔다.
- 문제 없음 상태와 완료 상태를 시각적, 문구적으로 구분한다.

## 상태 및 예외 처리

- `loading_progress`: 완료 화면 표시 전 최신 진행 상태를 확인 중이다.
- `completed`: 오늘 학습 완료 상태다.
- `promotion_granted`: 포인트 지급이 완료된 상태다.
- `promotion_pending`: 포인트 지급 확인이 진행 중인 상태다.
- `promotion_failed`: 학습은 끝났지만 포인트 지급 요청 또는 확인이 실패한 상태다.
- `already_granted`: 이미 오늘 보상이 지급된 상태다.
- `error`: 진행 상태 조회 실패 또는 응답 형식 오류가 발생했다.
- 진행 상태 조회 실패 시 문제 풀이 화면으로 낙관적으로 이동하지 않는다.
- 완료 상태인데 문제 데이터가 없는 경우에도 완료 분기를 우선한다.
- 지급 처리 중 상태에서 사용자가 여러 번 완료 화면에 들어와도 지급 요청을 자동 반복하지 않는다.
- 지급 실패 상태에서는 사용자가 상태 확인 또는 재시도를 할 수 있는 연결점을 제공하되, 완료 상태 자체를 취소하지 않는다.
- KST 자정이 지나면 새 `quizDate` 기준으로 진행 상태를 다시 확인한다.

## 완료 기준

- 오늘 학습 완료 사용자는 완료 화면을 볼 수 있다.
- 완료 화면에는 문제 다시 풀기 CTA가 없다.
- 앱 재진입 또는 새로고침 후에도 완료 사용자는 문제 풀이 화면이 아니라 완료 화면으로 이동한다.
- 포인트 지급 완료, 지급 대기, 지급 실패, 이미 지급 상태가 문구상 구분된다.
- 완료 상태와 문제 없음 상태가 혼동되지 않는다.
- 긴 설명, 통계, 캘린더, 공유, 추천 콘텐츠가 포함되지 않는다.
- TDS 우선, 모바일 WebView safe area, 상단 맥락, 중앙 상태, 하단 주요 CTA 구조를 따른다.
- 15번 작업이 완료 화면 우선 분기와 중복 가드를 이어받을 수 있다.

## Git 전략

- 최신 `dev` 기준에서 `codex/14-today-complete-screen` 형식의 작업 브랜치를 만든다.
- 의미 있는 기능 단위마다 커밋한다.
- 작업 완료 후 같은 번호의 completed 문서를 작성한다.
- 작업 브랜치에서 `dev`로 PR을 보낸다.
- 예외가 필요한 작업은 이 섹션에 예외 사유와 진행 방식을 명시한다.
- 포인트 지급 상태 API가 준비되지 않았다면 진행 상태 mock으로 화면 상태만 검증하고 completed 문서에 남긴다.
