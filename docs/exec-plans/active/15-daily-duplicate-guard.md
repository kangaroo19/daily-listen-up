# 15. 당일 중복 학습 및 중복 보상 방지 처리

## 목적

같은 사용자가 같은 날짜에 문제 풀이, 답안 제출, 결과 확인, 포인트 지급을 중복으로 실행하지 않게 한다.

이 작업은 서버의 멱등 처리를 대체하는 작업이 아니라, 프론트에서 잘못된 화면 진입과 중복 요청을 막고 서버 응답에 맞게 올바른 화면으로 이동시키는 작업이다.

## 구현 범위

- `userKey + quizDate` 기준 진행 상태를 앱 진입, 문제 시작, 제출, 결과 확인, 포인트 지급, 재도전 권한 부여 전에 확인한다.
- 완료 사용자가 문제 풀이 화면으로 다시 진입하지 못하게 한다.
- 이미 제출된 사용자가 같은 답안을 중복 제출하지 못하게 한다.
- 전면형 광고 완료 전 결과 확인을 막는다.
- 이미 지급된 사용자가 포인트 지급 요청을 반복하지 못하게 한다.
- 보상형 광고 완료 전 오답 재도전을 막는다.
- 서버의 `409`, `403`, `already_*` 계열 응답을 진행 상태 재조회와 라우팅으로 연결한다.
- KST 자정 이후 이전 날짜 상태가 새 날짜 흐름에 섞이지 않게 한다.
- 흐름별 우선순위와 차단 화면 기준을 정리한다.

## 제외 범위

- 서버의 원자적 멱등 처리 구현
- 서버의 부정 사용 탐지, 속도 제한, 운영자 수동 조정
- Firebase 보안 규칙 전체 설계
- 새로운 학습 상태나 보상 정책 추가
- 통계, 로그 분석, 관리자 화면
- 오답 재도전 횟수 제한 정책 변경
- 오늘 문제 없음 화면 최종 구현
- completed 문서 작성

## 구현 기준

- 중복 방지의 최종 판정은 서버와 저장된 진행 상태를 기준으로 한다.
- 프론트는 낙관적으로 지급 완료나 학습 완료를 확정하지 않는다.
- 날짜 기준은 4번 작업의 KST `quizDate` 계산을 재사용한다.
- 앱 진입 시 인증 상태, 오늘 진행 상태, 오늘 문제 조회 결과를 함께 확인한다.
- 분기 우선순위는 `완료 상태`, `진행 상태`, `오늘 문제 있음/없음`, `오류 상태` 순서로 명확히 둔다.
- 이미 `completed` 또는 `isPromotionGranted: true`이면 문제 풀이, 제출, 광고, 보상 요청 화면으로 보내지 않는다.
- `promotionStatus: granted` 또는 서버의 `already_granted` 응답은 정상 완료 계열로 처리한다.
- `submitted` 상태에서 같은 선택지 제출을 반복하지 않고 전면형 광고 또는 결과 확인 가능 상태로 이동한다.
- 전면형 광고 완료가 서버에 반영되지 않은 상태에서는 결과 확인 API를 호출하지 않는다.
- `incorrect` 상태에서 `hasEarnedRetry: false`이면 문제 풀이 재진입을 차단하고 보상형 광고 재도전 흐름으로 보낸다.
- `incorrect` 상태에서 `hasEarnedRetry: true`이면 같은 문제 재도전을 허용한다.
- 보상형 광고의 `dismissed`만 발생한 상태는 재도전 가능 상태로 보지 않는다.
- 지급 요청, 재도전 권한 반영, 제출 요청 중에는 CTA를 중복 실행할 수 없게 한다.
- API가 `409`를 반환하면 실패 문구를 바로 표시하기보다 진행 상태를 재조회한다.
- API가 `403`을 반환하면 현재 단계 권한이 없다고 보고 적절한 이전 또는 완료 화면으로 이동한다.
- 응답의 `quizDate`가 현재 KST `quizDate`와 다르면 현재 날짜 기준으로 다시 조회한다.
- 상태 재조회 실패 시 사용자를 문제 풀이로 낙관적으로 보내지 않는다.

## 상태 및 예외 처리

- `checking_guard`: 중복 가드에 필요한 진행 상태를 확인 중이다.
- `ready`: 현재 단계로 진입할 수 있다.
- `completed_blocked`: 오늘 학습이 완료되어 현재 단계로 진입할 수 없다.
- `already_submitted`: 이미 답안을 제출한 상태다.
- `ad_required`: 결과 확인 전 전면형 광고 완료가 필요하다.
- `retry_locked`: 오답 후 보상형 광고 완료 전이라 재도전할 수 없다.
- `retry_ready`: 보상형 광고 완료 후 재도전할 수 있다.
- `already_granted`: 오늘 포인트가 이미 지급되었다.
- `stale_quiz_date`: 화면의 날짜와 현재 KST 날짜가 다르다.
- `conflict_recheck`: 서버 충돌 응답 후 진행 상태를 재조회해야 한다.
- `error`: 진행 상태 조회 실패, 응답 형식 오류, 알 수 없는 오류가 발생했다.
- 가드 확인 중에는 주요 CTA를 비활성화한다.
- 충돌 응답 후 재조회가 실패하면 중복 요청을 반복하지 않고 오류 상태를 보여준다.
- 완료 상태와 오늘 문제 없음 상태가 동시에 보일 수 있는 상황에서는 완료 상태를 우선한다.
- 오늘 문제 없음 상태에서는 제출, 광고, 보상 API를 호출하지 않는다.

## 완료 기준

- 완료 사용자는 문제 풀이 화면으로 재진입하지 않는다.
- 이미 제출된 사용자는 같은 답안을 중복 제출하지 않는다.
- 전면형 광고 완료 전 결과 확인 API가 호출되지 않는다.
- 이미 지급된 사용자는 포인트 지급 요청을 반복하지 않고 완료 화면으로 이동한다.
- 오답 사용자는 `userEarnedReward` 이후 서버 반영 전까지 재도전할 수 없다.
- `409`, `403`, `already_*` 응답이 무시되지 않고 진행 상태 재조회와 올바른 라우팅으로 처리된다.
- KST 자정 이후 이전 날짜 상태가 새 날짜 문제 흐름에 섞이지 않는다.
- 서버 멱등 처리 구현이나 부정 사용 탐지 고도화가 포함되지 않는다.
- 11~13번에서 만든 보상, 재도전, 완료 화면 흐름이 같은 상태 용어를 사용한다.
