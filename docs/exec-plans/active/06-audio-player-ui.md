# 6. 오디오 재생 UI 구현

## 목적

사용자가 오늘 문제의 영어 오디오를 안정적으로 재생하고, 듣기 학습을 시작할 수 있게 한다.

이 작업은 문제 풀이 페이지 안에서 오디오를 듣는 경험만 다루며, 선택지 풀이와 답안 제출은 후속 작업에서 구현한다.

## 구현 범위

- 오늘 문제 데이터의 `audioUrl`을 사용해 오디오 재생 UI를 구현한다.
- 재생, 일시정지, 다시 재생 액션을 제공한다.
- 오디오 메타데이터 로딩, 재생 준비, 재생 중, 일시정지, 종료 상태를 구분한다.
- 현재 재생 시간과 전체 길이를 사용자가 이해할 수 있게 표시한다.
- 오디오 로딩 실패와 재시도 상태를 처리한다.
- 모바일 WebView에서 사용자의 명시적인 탭 이후 재생되도록 한다.
- 문제 풀이 페이지의 오디오 영역을 이후 객관식 UI와 함께 배치할 수 있게 만든다.

## 제외 범위

- 객관식 질문과 선택지 UI 구현
- 답안 선택 상태와 제출 CTA 구현
- 답안 제출 API 호출
- 전면형 광고, 보상형 광고 호출
- 정답, 오답, 결과 화면 구현
- 스크립트, 해설, 정답 선택지 노출
- 재생 속도 조절, 구간 반복, 북마크, 다운로드, 자막 기능
- 오디오 파일 업로드 또는 운영 관리 기능
- completed 문서 작성

## 구현 기준

- 4번 작업에서 정의한 문제 데이터의 `audioUrl`을 입력으로 사용한다.
- `audioUrl`은 HTTPS 원격 URL을 기준으로 처리한다.
- 오디오 재생은 `HTMLAudioElement` 또는 WebView에서 호환되는 브라우저 오디오 API를 사용한다.
- WebView 자동재생을 기대하지 않고 사용자의 재생 버튼 선택 이후 `play()`를 호출한다.
- 오디오 제어 로직은 페이지 컴포넌트에 흩어두지 않고 오디오 플레이어 컴포넌트 또는 기능 영역으로 분리한다.
- `audioUrl` 또는 `quizDate`가 바뀌면 이전 오디오 상태, 이벤트 리스너, 재생 위치를 초기화한다.
- 컴포넌트 언마운트 시 오디오 이벤트 리스너를 정리하고 재생 중인 오디오를 멈춘다.
- 재생 버튼은 기능을 바로 이해할 수 있는 아이콘 또는 TDS 기준의 버튼을 우선 사용한다.
- 아이콘만 사용하는 버튼에는 접근성 라벨을 제공한다.
- 진행률 표시는 레이아웃이 흔들리지 않도록 고정된 영역 안에 둔다.
- 오디오 로딩 중에는 사용자가 여러 번 재생을 요청해도 중복 `play()` 호출로 상태가 꼬이지 않게 한다.
- 오디오 재생 실패 시 문제 풀이 화면 전체를 비우지 않고 오디오 영역 안에서 실패 상태를 보여준다.
- 스크립트와 정답 관련 데이터는 이번 UI에 전달하거나 표시하지 않는다.
- 오디오 영역은 이후 7번 객관식 UI가 아래에 배치될 수 있도록 과도하게 화면을 차지하지 않는다.

## 상태 및 예외 처리

- `idle`: 오디오 URL은 있지만 아직 사용자가 재생을 시작하지 않았다.
- `loading_metadata`: 오디오 메타데이터를 불러오는 중이다.
- `ready`: 재생할 수 있는 상태다.
- `playing`: 오디오가 재생 중이다.
- `paused`: 사용자가 일시정지했거나 재생이 멈춘 상태다.
- `ended`: 오디오 재생이 끝났다.
- `buffering`: 재생 중 네트워크 상태로 버퍼링이 발생했다.
- `error`: 오디오 URL 오류, 네트워크 오류, 포맷 미지원, 재생 권한 오류가 발생했다.
- `audioUrl`이 비어 있거나 유효하지 않으면 재생 버튼을 활성화하지 않는다.
- `play()` Promise가 실패하면 오류 상태로 전환하고 재시도 기준을 제공한다.
- 네트워크가 느려 메타데이터 로딩이 길어져도 빈 영역으로 남기지 않는다.
- 오디오가 끝나면 다시 들을 수 있는 상태로 전환한다.
- 페이지를 떠날 때 재생 중인 오디오는 멈춘다.

## 완료 기준

- 오늘 문제의 `audioUrl`로 오디오를 재생할 수 있다.
- 사용자는 재생 중, 일시정지, 종료 상태를 구분할 수 있다.
- 오디오 로딩 중과 실패 상태가 빈 화면이나 무한 로딩 없이 표시된다.
- 사용자가 명시적으로 재생 버튼을 누른 뒤 오디오가 재생된다.
- 재생 중 페이지 이탈 또는 문제 변경 시 오디오가 정리된다.
- 스크립트, 정답, 결과 정보가 노출되지 않는다.
- 선택지 UI, 제출 흐름, 광고 흐름, 결과 흐름이 포함되지 않는다.
- 모바일 WebView에서 하단 CTA와 겹치지 않는 문제 풀이 페이지 영역으로 배치할 수 있다.
- 로컬 브라우저와 Apps in Toss WebView에서 기본 재생 동작을 확인할 수 있는 기준이 있다.
