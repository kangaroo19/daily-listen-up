# 05. 오디오 재생과 복수응답 퀴즈 UI 구현

## 목적

문제 풀이 화면에서 오늘의 영어 오디오를 사용자가 직접 1회 듣고, 청취 완료 후 5개 선택지 중 정답이라고 생각하는 항목을 여러 개 선택할 수 있게 한다.
이 작업은 답안 제출과 광고 흐름을 붙이기 전까지의 퀴즈 풀이 UI와 상태 제어를 완성한다.

- 필요한 배경 확인용: `INTRODUCE.md`

## 범위

- 문제 풀이 화면 진입 시 앱 세션 토큰과 함께 `GET /api/today-quiz`를 호출한다.
- 응답의 `quizDate`, `audioUrl`, `choices`를 화면 상태에 보관한다.
- 오디오는 자동 재생하지 않고 사용자가 `듣기 시작`을 눌렀을 때만 재생한다.
- 각 시도에서 오디오는 1회만 들을 수 있게 제어한다.
- 오디오 청취가 끝나기 전에는 선택지를 보여주지 않는다.
- 청취 완료 후 5개 선택지를 표시하고 복수 선택을 지원한다.
- 최소 1개 이상 선택해야 `답안 제출` 버튼을 활성화한다.
- 제출 버튼은 다음 작업에서 답안 제출/전면형 광고를 연결할 수 있게 선택 답안과 `quizDate`를 보관한 상태로 둔다.

## 제외 범위

- 답안 제출 API 호출, 결과 확인 전면형 광고, 정답 검증은 06번 작업에서 다룬다.
- 결과 화면, 재도전, 스크립트 보기, 포인트 지급은 구현하지 않는다.
- 정답 선택지, 스크립트, 포인트 금액을 클라이언트에서 요구하거나 노출하지 않는다.
- 오답 후 보상형 광고 완료로 재도전권을 얻는 흐름은 이 작업에서 구현하지 않는다.
- 문제 콘텐츠 제작 도구나 관리자 화면은 만들지 않는다.

## 작업 체크리스트

- [ ] 작업 시작 시 `docs/exec-plans/completed/04-home-today-quiz-entry-result.md`가 존재하면 먼저 읽고 문제 풀이 화면 경로와 앱 세션 사용 방식을 반영한다.
- [ ] 문제 풀이 화면 진입 시 `GET /api/today-quiz`를 호출한다.
- [ ] `GET /api/today-quiz` 응답의 `quizDate`를 상태에 보관하고 이후 제출 작업에서 사용할 수 있게 한다.
- [ ] `GET /api/today-quiz` 응답의 `audioUrl`로 오디오를 재생할 수 있게 한다.
- [ ] `GET /api/today-quiz` 응답의 `choices` 5개를 청취 완료 후 표시한다.
- [ ] 청취 전 제목 `오늘의 영어를 들어보세요`와 안내 `음성을 끝까지 들은 뒤 문제를 풀 수 있어요.`를 표시한다.
- [ ] 오디오는 자동 재생하지 않고 `듣기 시작` 버튼으로만 시작한다.
- [ ] 오디오 재생이 시작된 뒤 같은 시도에서 다시 재생할 수 없게 한다.
- [ ] 오디오 종료 이벤트 이후 제목을 `정답이라고 생각하는 답을 모두 골라주세요`로 전환한다.
- [ ] 오디오 청취 완료 전에는 선택지를 숨기거나 비활성 상태로 유지한다.
- [ ] 청취 완료 후 5개 선택지에서 여러 개를 선택하거나 선택 해제할 수 있게 한다.
- [ ] 선택 개수에는 별도 상한을 두지 않는다.
- [ ] 선택 답안이 0개이면 `답안 제출` 버튼을 비활성화한다.
- [ ] 선택 답안이 1개 이상이면 `답안 제출` 버튼을 활성화한다.
- [ ] 문제 또는 오디오 로딩 실패 시 `문제를 불러오지 못했어요.`와 `다시 시도` 액션을 같은 화면에 표시한다.
- [ ] `답안 제출` 버튼에는 텍스트와 광고/영상 성격의 아이콘을 함께 배치할 수 있는 구조를 둔다.

## 검증 체크리스트

- [ ] 문제 풀이 화면 진입 시 앱 세션 토큰으로 `GET /api/today-quiz`가 호출된다.
- [ ] 서버 응답의 `quizDate`가 상태에 보관되고 화면 이탈 전까지 유지된다.
- [ ] 오디오가 자동 재생되지 않는다.
- [ ] 사용자가 `듣기 시작`을 누르면 오디오가 재생된다.
- [ ] 같은 시도에서 오디오를 두 번째로 재생할 수 없다.
- [ ] 오디오가 끝나기 전에는 선택지가 표시되지 않거나 선택할 수 없다.
- [ ] 오디오가 끝난 뒤 정확히 5개 선택지가 표시된다.
- [ ] 사용자가 선택지를 여러 개 선택하고 다시 해제할 수 있다.
- [ ] 선택 답안이 0개이면 `답안 제출` 버튼이 비활성화된다.
- [ ] 선택 답안이 1개 이상이면 `답안 제출` 버튼이 활성화된다.
- [ ] API 또는 오디오 로딩 실패 시 같은 화면에서 다시 시도할 수 있다.
- [ ] 클라이언트 응답 또는 상태에 `correctChoiceIds`, `script`, `promotionAmount`, 원본 `audioStoragePath`가 필요 이상으로 노출되지 않는다.
- [ ] 모바일 WebView 기준으로 주요 콘텐츠와 하단 액션이 겹치지 않는다.
- [ ] 타입 검사, 프론트 빌드, 관련 테스트 또는 수동 검증이 통과한다.
