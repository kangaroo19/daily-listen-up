# 5. 오늘의 문제 진입 화면 구현

## 목적

사용자가 앱에 들어왔을 때 오늘 문제를 풀 수 있는지 바로 이해하고, 가능한 다음 행동 하나를 선택할 수 있게 한다.

이 작업은 로그인 이후 첫 진입 경험을 만드는 작업이며, 3번 진행 상태와 4번 문제 조회 결과를 조합해 시작 가능, 완료, 문제 없음, 오류 상태를 분기한다.

## 구현 범위

- 로그인 완료 후 오늘의 문제 진입 화면을 구현한다.
- 3번 작업의 사용자 진행 상태를 조회해 오늘 학습 가능 여부를 판단한다.
- 4번 작업의 오늘 문제 조회 결과를 사용해 시작 가능 여부를 판단한다.
- 오늘 문제 시작 가능 상태에서 주요 CTA를 제공한다.
- 이미 오늘 학습을 완료한 사용자는 시작 CTA 대신 완료 상태로 안내한다.
- 오늘 문제 데이터가 없으면 `오늘의 문제 준비 중` 상태를 보여준다.
- 진행 상태 또는 문제 조회 실패 시 재시도 가능한 오류 상태를 보여준다.
- 모바일 WebView safe area를 고려해 하단 주요 CTA가 안정적으로 보이게 한다.

## 제외 범위

- 토스 로그인 SDK 호출과 서버 로그인 API 구현
- 사용자 진행 상태 모델 자체의 재정의
- Firebase 문제 조회 로직 자체의 재정의
- 오디오 재생 UI 구현
- 객관식 선택지 UI와 답안 선택 상태 구현
- 답안 제출, 정답 검증, 결과 화면 구현
- 전면형 광고, 보상형 광고 호출 구현
- 포인트 지급 요청, 지급 성공/실패 상세 화면 구현
- 학습 기록, 캘린더, 연속 학습, 추천 콘텐츠
- 마케팅용 랜딩 페이지나 긴 튜토리얼 화면
- completed 문서 작성

## 구현 기준

- 화면의 목적은 `오늘 문제 시작` 하나로 제한한다.
- 진입 화면은 인증 완료, `quizDate` 계산 완료, 진행 상태 조회 완료, 오늘 문제 조회 완료 이후의 조합 상태를 기준으로 표시한다.
- 화면 컴포넌트는 Firebase SDK를 직접 호출하지 않고 진행 상태 조회 결과와 문제 조회 결과를 받아 분기한다.
- 화면 상단에는 오늘 학습 상태나 날짜 맥락을 짧게 표시한다.
- 화면 중앙에는 오늘 문제를 시작할 수 있는지 알 수 있는 핵심 문구와 최소 정보를 배치한다.
- 화면 하단에는 한 개의 주요 CTA를 둔다.
- 주요 CTA는 TDS `Button` 사용을 우선한다.
- CTA가 진행 중일 때는 `loading`과 `disabled` 상태를 적용한다.
- CTA는 모바일 WebView 하단 safe area와 겹치지 않아야 한다.
- 시작 가능 상태에서는 문제 풀이 페이지로 이동하는 CTA를 제공한다.
- 시작 CTA 연속 선택으로 라우팅, 진행 상태 생성, 조회 요청이 중복 실행되지 않게 한다.
- 시작 시 `in_progress` 진행 상태를 생성하거나 갱신해야 한다면, 해당 요청 실패 시 문제 풀이 페이지로 이동하지 않는다.
- 완료 상태에서는 시작 CTA를 제공하지 않는다.
- 완료 상태 사용자는 오늘 학습 완료 화면 또는 결과 페이지로 이동할 수 있는 기준만 제공한다.
- 오늘 문제 없음 상태에서는 문제 풀이 페이지로 이동할 수 없다.
- 오류 상태에서는 짧은 오류 문구와 재시도 CTA를 제공한다.
- 보상 금액을 표시해야 한다면 `정답 시 받을 수 있음` 수준으로 표현하고 지급 확정처럼 쓰지 않는다.
- 정답, 오답, 재도전, 포인트 지급 결과 문구는 이번 화면에서 상세히 다루지 않는다.
- 문구는 짧고 직접적으로 작성한다.
- 한 화면에 소개, 문제 풀이, 결과 안내를 동시에 넣지 않는다.

## 상태 및 예외 처리

- `checking`: 인증 상태, 진행 상태, 오늘 문제 데이터를 확인 중이다.
- `ready_to_start`: 오늘 문제 데이터가 있고 사용자가 아직 오늘 학습을 완료하지 않았다.
- `empty_quiz`: 오늘 날짜 문제 데이터가 없다.
- `already_completed`: 오늘 학습이 완료되어 다시 시작할 수 없다.
- `blocked`: 제출 중, 결과 확인 대기, 보상 처리 중처럼 문제 풀이로 바로 진입하면 안 되는 상태다.
- `error`: 진행 상태 조회 실패, 문제 조회 실패, 상태 조합 불일치가 발생했다.
- `checking` 상태에서는 빈 화면을 보여주지 않는다.
- `ready_to_start`가 아니면 시작 CTA를 활성화하지 않는다.
- `already_completed` 상태에서는 완료 화면 또는 결과 페이지로 이동하는 흐름만 허용한다.
- `blocked` 상태에서는 사용자가 지금 이어가야 할 후속 화면으로 이동하거나 짧은 안내 상태를 제공한다.
- `empty_quiz`는 오류가 아니므로 재시도와 별개로 준비 중 상태를 명확히 보여준다.
- 네트워크 오류나 권한 오류는 재시도 가능한 실패 상태로 처리한다.
- 진행 상태는 완료인데 문제 데이터가 없는 경우, 완료 분기를 우선해 문제 풀이 재진입을 막는다.
- 진행 상태 조회와 문제 조회 중 하나라도 실패하면 시작 CTA를 열지 않는다.
- 앱이 열린 채 KST 자정이 지나면 `quizDate`를 다시 계산한 뒤 진입 상태를 다시 확인한다.

## 완료 기준

- 로그인 완료 사용자가 오늘의 문제 진입 화면을 볼 수 있다.
- 오늘 문제 데이터가 있고 아직 완료하지 않은 사용자는 시작 CTA를 볼 수 있다.
- 시작 CTA 선택 시 문제 풀이 페이지로 이동할 수 있는 연결 지점이 준비되어 있다.
- CTA를 연속 선택해도 중복 이동이나 중복 상태 생성이 발생하지 않는다.
- 이미 오늘 학습을 완료한 사용자는 시작 CTA를 볼 수 없다.
- 오늘 문제 데이터가 없으면 `오늘의 문제 준비 중` 상태가 표시되고 문제 풀이로 이동하지 않는다.
- 진행 상태 조회 실패와 문제 조회 실패가 빈 화면이나 무한 로딩 없이 처리된다.
- 보상 문구가 지급 확정처럼 표현되지 않는다.
- 화면은 TDS 우선, 모바일 WebView safe area, 상단 맥락, 중앙 콘텐츠, 하단 주요 액션 구조를 따른다.
- 오디오 재생 UI, 객관식 UI, 결과 화면, 광고, 포인트 지급 구현이 포함되지 않는다.
- 6번과 7번 작업이 시작 CTA 이후의 문제 풀이 화면을 이어받을 수 있다.

## Git 전략

- 최신 `dev` 기준에서 `codex/05-today-quiz-entry` 형식의 작업 브랜치를 만든다.
- 의미 있는 기능 단위마다 커밋한다.
- 작업 완료 후 같은 번호의 completed 문서를 작성한다.
- 작업 브랜치에서 `dev`로 PR을 보낸다.
- 예외가 필요한 작업은 이 섹션에 예외 사유와 진행 방식을 명시한다.
- 문제 풀이 페이지 라우트가 아직 없으면 임시 연결 지점만 만들고, 실제 오디오와 선택지 UI는 후속 작업에서 구현한다.
