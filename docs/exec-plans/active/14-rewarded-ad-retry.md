# 14. 오답 시 보상형 광고 기반 재도전 구현

## 목적

오답을 낸 사용자가 보상형 광고를 끝까지 시청해 보상 이벤트를 받은 경우에만 같은 문제를 다시 풀 수 있게 한다.

이 작업은 재도전 권한을 얻는 흐름을 구현하는 작업이며, 광고를 닫기만 한 경우에는 재도전을 허용하지 않는다.

## 구현 범위

- 12번 작업에서 `incorrect`와 `nextStep: 'rewarded_retry'`로 분기된 경우에만 진입한다.
- 보상형 광고 전용 광고 그룹 ID를 사용한다.
- Apps in Toss 공식 광고 API의 `loadFullScreenAd`와 `showFullScreenAd`를 사용한다.
- 광고 기능 지원 여부를 `isSupported()`로 확인한다.
- 보상형 광고 로드, 표시, 보상 획득, 닫힘, 실패 상태를 구분한다.
- `userEarnedReward` 이벤트가 발생한 경우에만 재도전 권한 반영 API를 호출한다.
- 광고를 닫기만 한 경우에는 재도전 CTA를 열지 않는다.
- 재도전 권한 반영 성공 후 같은 `quizDate` 문제 풀이 화면으로 돌아갈 수 있게 한다.
- 광고 콜백 등록 해제와 중복 호출 방지 기준을 정의한다.

## 제외 범위

- 전면형 광고 연동 변경
- 답안 제출과 결과 확인 흐름 재구현
- 정답 시 포인트 지급 요청
- 재도전 횟수 제한
- 다른 문제 제공, 랜덤 문제, 복습 문제
- 광고 수익 분석, 클릭 분석, A/B 테스트
- 서버의 재도전 권한 저장과 멱등 처리 구현
- completed 문서 작성

## 구현 기준

- 오답 결과 이후에만 보상형 광고 재도전 화면으로 진입한다.
- 정답 사용자나 완료 사용자는 보상형 광고 재도전 흐름으로 진입하지 않는다.
- 전면형 광고용 `adGroupId`와 보상형 광고용 `adGroupId`를 분리한다.
- 광고 타입은 광고 그룹 ID로 결정되므로 보상형 광고 그룹 ID를 잘못 사용하지 않게 설정 기준을 둔다.
- 보상형 광고 연동은 화면 컴포넌트에 직접 흩어두지 않고 `lib/toss-ads` 또는 같은 역할의 래퍼를 재사용한다.
- `loadFullScreenAd.isSupported()`와 `showFullScreenAd.isSupported()`를 확인한다.
- 광고는 `load → loaded 이벤트 → show` 순서로 호출한다.
- 같은 보상형 `adGroupId`에 대해 동시에 여러 광고를 로드하지 않는다.
- 광고 표시 중에는 CTA를 중복 실행할 수 없게 한다.
- `userEarnedReward` 이벤트가 발생한 뒤에만 재도전 권한 반영 API를 호출한다.
- `dismissed` 이벤트만으로 재도전 권한을 지급하지 않는다.
- `failedToShow` 또는 `onError` 발생 시 재도전 권한을 지급하지 않는다.
- 재도전 권한 반영 API는 `POST /api/quiz-submissions/{submissionId}/rewarded-retry`를 기준으로 한다.
- 요청 본문은 `{ quizDate: string; adGroupId: string; reward: { unitType: string; unitAmount: number } }`를 기준으로 한다.
- 성공 응답은 `{ hasEarnedRetry: true; status: 'in_progress'; attemptCount: number }`를 기준으로 한다.
- 서버가 이미 재도전 권한을 부여한 상태를 반환하면 성공 계열로 처리하고 문제 풀이로 이동한다.
- 재도전 시작 시 기존 선택 답안과 제출 결과는 초기화한다.
- 같은 `quizDate`와 같은 문제 데이터로 다시 풀게 한다.
- 재도전 후 답안 제출은 10번, 전면형 광고는 11번, 결과 확인은 12번 흐름을 재사용한다.

## 상태 및 예외 처리

- `checking_support`: 보상형 광고 API 지원 여부를 확인 중이다.
- `unsupported`: 광고 API를 사용할 수 없는 환경이다.
- `loading_ad`: 보상형 광고를 로드 중이다.
- `loaded`: 광고가 로드되어 표시할 수 있다.
- `showing`: 광고를 표시 중이다.
- `reward_earned`: `userEarnedReward` 이벤트를 받았다.
- `dismissed_without_reward`: 광고가 닫혔지만 보상 이벤트가 없었다.
- `granting_retry`: 재도전 권한을 서버에 반영 중이다.
- `retry_ready`: 재도전 권한 반영이 완료되어 문제를 다시 풀 수 있다.
- `failed_to_load`: 광고 로드에 실패했다.
- `failed_to_show`: 광고 표시에 실패했다.
- `error`: 재도전 권한 반영 실패 또는 알 수 없는 오류가 발생했다.
- 광고 미지원 상태에서는 바로 재도전을 허용하지 않는다.
- 광고를 닫기만 한 경우 짧은 안내와 다시 광고 보기 CTA를 제공한다.
- `userEarnedReward` 이벤트가 여러 번 들어와도 재도전 권한 반영 API는 중복 호출되지 않게 한다.
- 서버 반영 실패 시 재도전 화면으로 이동하지 않는다.
- 화면을 벗어나면 광고 콜백이 이전 화면 상태를 덮어쓰지 않게 한다.
- 이미 오늘 학습을 완료한 상태로 바뀌면 재도전 흐름을 중단하고 완료 흐름으로 이동한다.

## 완료 기준

- 오답 결과 이후에만 보상형 광고 재도전 흐름에 진입한다.
- 보상형 광고 지원 여부와 광고 그룹 ID 설정을 확인한다.
- 광고는 `load → loaded 이벤트 → show` 순서로 호출된다.
- `userEarnedReward` 이벤트가 없으면 재도전 CTA가 열리지 않는다.
- 광고 `dismissed`만으로 재도전 권한을 지급하지 않는다.
- 보상 이벤트 이후 서버 재도전 권한 반영이 성공해야 같은 문제를 다시 풀 수 있다.
- 재도전 시 기존 선택과 제출 상태가 초기화된다.
- 재도전 후 제출, 전면형 광고, 결과 확인은 기존 9~12번 흐름을 재사용할 수 있다.
- 전면형 광고와 보상형 광고 상태명, 광고 그룹 ID, 이벤트 처리가 섞이지 않는다.
