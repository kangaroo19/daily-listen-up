# 백엔드

## 목적

클라이언트에서 직접 처리하면 안 되는 로그인, 사용자 식별, 정답 검증, 포인트 지급, 중복 지급 방지 책임을 서버에서 처리한다.

## 기본 전제

- 백엔드 코드는 초기에는 이 프로젝트 내부에 둔다.
- 배포 직전 Firebase Functions로 옮길 수 있는 구조를 전제로 한다.
- 클라이언트에는 공개 가능한 값만 둔다.
- 토큰, 서버 비밀키, 포인트 지급에 필요한 민감한 값은 서버에서만 다룬다.

## 서버가 담당할 제품 책임

- 토스 로그인 인가 코드 처리
- 토스 사용자 식별값 확보
- 오늘 문제에 대한 정답 검증
- 정답 사용자에 대한 포인트 지급 요청
- 하루 1회 보상 지급 보장
- 중복 요청에 대한 중복 지급 방지
- 지급 결과 저장과 재조회 기준 제공

## 토스 로그인 기준

- 클라이언트는 `appLogin()`으로 인가 코드만 받는다.
- 인가 코드의 토큰 교환, access token 발급, 사용자 정보 조회는 서버에서 처리한다.
- 인가 코드는 클라이언트에서 장기간 저장하지 않는다.
- access token, refresh token 같은 민감한 정보는 서버에서 안전하게 보관한다.

## 아직 확정하지 않는 것

- API endpoint 경로와 요청/응답 형식
- 서버 내부 폴더 구조
- Firebase Functions 이전 방식
- 데이터베이스 스키마
- 토스 포인트 지급 API의 구체적인 연동 방식
- 정답 검증 요청과 지급 요청의 세부 에러 코드
