# 9. 토스애즈 전면형 광고 연동

## 목적

사용자가 답안을 제출한 뒤 정답 여부를 확인하기 전에 토스애즈 전면형 광고를 보도록 한다.

이 작업은 `정답 확인 전 광고 정책`을 구현하는 게이트이며, 광고가 완료된 뒤에만 10번 결과 확인 흐름으로 넘어갈 수 있게 한다.

## 구현 범위

- 제출 성공 후 전면형 광고 화면 또는 광고 대기 상태로 진입한다.
- Apps in Toss 공식 광고 API의 `loadFullScreenAd`와 `showFullScreenAd`를 사용한다.
- 광고 기능 지원 여부를 `isSupported()`로 확인한다.
- 전면형 광고 그룹 ID를 설정에서 읽는 기준을 만든다.
- 광고 로드, 로드 완료, 표시 요청, 표시 중, 닫힘, 실패 상태를 구분한다.
- 광고는 `load → loaded 이벤트 → show` 순서로 호출한다.
- 광고 표시 후 `dismissed` 이벤트를 결과 확인 가능 조건으로 사용한다.
- 광고 완료 상태를 서버에 반영하는 API 인터페이스를 정의한다.
- 광고 콜백 등록 해제와 중복 호출 방지 기준을 정의한다.

## 제외 범위

- 답안 제출 API 구현
- 정답, 오답 결과 화면 구현
- 서버의 정답 검증 로직 구현
- 포인트 지급 요청과 지급 결과 표시
- 보상형 광고 연동과 `userEarnedReward` 처리
- 오답 후 재도전 권한 지급
- 광고 수익 분석, 클릭 분석, A/B 테스트
- 배너 광고, 네이티브 광고, 다른 광고 네트워크 직접 연동
- completed 문서 작성

## 구현 기준

- 8번 작업에서 제출 성공 후 받은 `submissionId`가 있어야 전면형 광고 단계로 진입한다.
- 제출 성공 전에는 전면형 광고를 호출하지 않는다.
- 전면형 광고 연동은 화면 컴포넌트에 직접 흩어두지 않고 `lib/toss-ads` 또는 같은 역할의 래퍼로 분리한다.
- 공식 문서 기준으로 `loadFullScreenAd.isSupported()`와 `showFullScreenAd.isSupported()`를 확인한다.
- 광고 미지원 환경에서는 결과를 바로 보여주지 않고 광고 확인이 필요한 상태로 안내한다.
- 광고 그룹 ID는 전면형 광고용 값과 보상형 광고용 값을 분리한다.
- 전면형 광고 그룹 ID가 없으면 광고 호출을 시도하지 않고 설정 오류 상태로 처리한다.
- 화면 진입 시 광고를 미리 로드한다.
- 광고 로드 완료 이벤트를 받기 전에는 `showFullScreenAd`를 호출하지 않는다.
- 같은 `adGroupId`에 대해 동시에 여러 광고를 로드하지 않는다.
- 광고는 `load → show → 다음 load` 순서를 따른다.
- 광고 표시 중에는 사용자가 광고 CTA를 중복 실행할 수 없게 한다.
- `showFullScreenAd` 이벤트 중 `requested`, `show`, `impression`, `clicked`, `dismissed`, `failedToShow`를 구분한다.
- 전면형 광고에서는 `userEarnedReward`를 재도전 권한 지급 기준으로 사용하지 않는다.
- 광고가 `show` 또는 `impression` 이후 `dismissed`되면 광고 확인 완료로 본다.
- 광고 완료 후 `POST /api/quiz-submissions/{submissionId}/interstitial-complete`를 호출해 서버에 완료 상태를 반영한다.
- 완료 반영 API 요청 본문은 `{ quizDate: string; adGroupId: string }`를 기준으로 한다.
- 완료 반영 API 성공 응답은 `{ canViewResult: true }`를 기준으로 한다.
- 클라이언트 광고 이벤트만으로 결과 확인 권한을 최종 확정하지 않고 서버 응답과 결합한다.
- 광고 로드와 표시 API가 반환하는 unregister 함수를 언마운트 시 호출한다.
- 광고 실패 시 정답을 바로 보여주는 fallback을 만들지 않는다.

## 상태 및 예외 처리

- `checking_support`: 현재 환경에서 전면형 광고 API를 사용할 수 있는지 확인 중이다.
- `unsupported`: 광고 API를 사용할 수 없는 환경이다.
- `loading_ad`: 전면형 광고를 로드 중이다.
- `loaded`: 광고가 로드되어 표시할 수 있다.
- `showing`: 광고 표시를 요청했거나 광고가 표시 중이다.
- `dismissed`: 사용자가 광고를 닫았고 결과 확인 완료 반영을 시작할 수 있다.
- `completing`: 광고 완료 상태를 서버에 반영 중이다.
- `completed`: 서버가 결과 확인 가능 상태를 반환했다.
- `failed_to_load`: 광고 로드에 실패했다.
- `failed_to_show`: 광고 표시에 실패했다.
- `error`: 광고 완료 반영 API 실패 또는 알 수 없는 오류가 발생했다.
- 광고 로드 실패 시 사용자가 다시 시도할 수 있는 CTA를 제공한다.
- 광고 표시 실패 시 정답을 열지 않고 광고 재시도 또는 정책 확인이 필요한 상태로 둔다.
- 광고가 닫히기 전에는 결과 확인 API를 호출하지 않는다.
- 서버 완료 반영 실패 시 결과 화면으로 이동하지 않는다.
- 사용자가 화면을 벗어나면 광고 콜백이 이후 상태를 덮어쓰지 않게 한다.
- 로컬 브라우저처럼 광고 API가 미지원인 환경은 개발용 안내 상태로 분리한다.

## 완료 기준

- 제출 성공 상태와 `submissionId`가 있을 때만 전면형 광고 흐름에 진입한다.
- 전면형 광고 지원 여부를 확인한다.
- 광고는 `load → loaded 이벤트 → show` 순서로 호출된다.
- 광고 로드 전 또는 표시 중에는 중복 호출이 발생하지 않는다.
- 광고가 `dismissed`되기 전에는 결과 확인 흐름으로 이동하지 않는다.
- 광고 완료 후 서버 완료 반영 API가 성공해야 결과 확인 가능 상태가 된다.
- 광고 실패 시 정답/오답 결과가 바로 노출되지 않는다.
- 전면형 광고와 보상형 광고 상태명, 광고 그룹 ID, 이벤트 처리가 섞이지 않는다.
- 광고 콜백 unregister 처리가 정의되어 있다.
- 공식 Apps in Toss 광고 문서의 지원 여부, 호출 순서, 에러 처리 기준을 따른다.
