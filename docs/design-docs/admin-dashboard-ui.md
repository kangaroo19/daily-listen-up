# 관리자 대시보드 UI 기준

## 목적

이 문서는 관리자페이지 v1의 대시보드 UI 기준을 정의한다.

관리자 앱은 일반 사용자용 Apps in Toss 미니앱과 분리된 별도 운영 웹앱이다.
따라서 사용자 앱의 모바일 WebView 흐름을 그대로 따르기보다, 운영자가 날짜별 듣기 문제를 빠르게 작성, 확인, 발행할 수 있는 데스크톱 우선 대시보드로 설계한다.

기능과 운영 정책은 `docs/product-specs/admin.md`를 기준으로 하고, 공통 UI 원칙은 `docs/design-docs/style-guidelines.md`를 참고한다.

## 기본 방향

- 데스크톱 우선으로 설계한다.
- 조용한 SaaS형 운영 도구처럼 보이게 한다.
- 흰 배경, 얇은 선, 작은 상태 배지, 정돈된 표, 밀도 있는 폼을 기본으로 한다.
- 장식보다 운영 속도와 상태 식별성을 우선한다.
- 관리자 1명이 반복적으로 쓰는 도구라는 전제로, 학습용 안내보다 작업 효율을 우선한다.
- 새 디자인 시스템을 만들지 않고, 필요한 범위에서만 관리자 앱 전용 레이아웃과 상태 표현을 둔다.

## 화면 구조

기본 화면은 얇은 좌측 사이드바와 메인 대시보드로 구성한다.

좌측 사이드바는 v1에서 최소 항목만 제공한다.

- `퀴즈 관리`
- `오디오/TTS`
- `설정`

메인 상단에는 운영 요약을 작게 둔다.

- 오늘 문제 상태
- 내일 문제 상태
- 미발행 문제 수
- 발행 해제 문제 수
- 주의가 필요한 문제 수
- `새 퀴즈` 주요 액션

메인 본문은 목록/상세 2패널 구조로 둔다.

- 왼쪽 패널: 날짜별 퀴즈 목록, 발행 상태, 진행 기록 여부, 간단 필터
- 오른쪽 패널: 선택된 퀴즈의 상세 편집 폼

목록에서 퀴즈를 선택하면 오른쪽 상세 패널이 해당 퀴즈 기준으로 갱신된다.
같은 날짜의 문서가 이미 있으면 신규 등록 대신 기존 퀴즈 상세를 열도록 안내한다.

## 상세 편집 패널

상세 편집은 탭이나 단계형 마법사가 아니라 섹션형 한 화면 폼으로 구성한다.
입력 누락과 검증 오류가 숨겨지지 않도록 주요 입력을 세로 흐름 안에서 확인할 수 있어야 한다.

섹션 순서는 아래 기준을 따른다.

1. 기본 정보
   - `quizDate`
   - 발행 상태
   - 진행 기록 여부
2. 선택지
   - 선택지 5개
   - 정답 체크
3. 스크립트
   - 듣기 스크립트 입력
4. 오디오
   - 직접 mp3 업로드
   - TTS 미리듣기
   - `이 음성 사용`
5. 미리보기
   - 사용자에게 보일 문제 형태 확인
6. 운영 액션
   - 저장
   - 발행
   - 발행 해제
   - 삭제

진행 기록이 있는 퀴즈는 잠긴 필드를 비활성화하고, 잠금 사유를 해당 섹션 근처에 짧게 표시한다.
저장 전 검증 실패는 화면 상단에만 모으지 않고, 가능한 한 문제가 있는 섹션 가까이에 표시한다.

## 상태와 경고 표현

상태 색상은 장식이 아니라 기능적으로만 사용한다.

- 발행: 안정 또는 성공 계열
- 미발행: 중립 또는 주의 계열
- 발행 해제: 위험 계열
- 진행 기록 있음: 잠금 또는 주의 배지
- 저장 실패: 위험 계열
- TTS 실패: 주의 계열

진행 기록이 있는 퀴즈를 수정하거나 발행 해제할 때는 경고를 명확히 표시한다.
경고는 길게 설명하기보다 사용자가 실제로 이해해야 하는 영향을 짧게 보여준다.

- 진행 기록이 있는 퀴즈는 판정과 보상에 영향 있는 필드를 수정할 수 없다.
- 발행 해제는 기존 진행자의 재도전과 스크립트 열람도 막는다.
- 기존 사용자 진행 기록과 보상 기록은 소급 변경하지 않는다.

## 액션 배치

주요 액션은 작업 흐름에 맞춰 배치한다.

- `새 퀴즈`는 메인 상단의 눈에 띄는 위치에 둔다.
- `저장`은 상세 편집 패널 하단 또는 고정 액션 영역에 둔다.
- `발행`은 저장된 미발행 퀴즈에서 명확하게 보이게 한다.
- `발행 해제`와 `삭제`는 위험 액션으로 구분하고, 기본 주요 액션처럼 보이지 않게 한다.
- `TTS 미리듣기`는 스크립트와 오디오 섹션 사이 흐름에서 실행할 수 있게 한다.
- `이 음성 사용`은 TTS 미리듣기 결과를 확인한 뒤 누를 수 있게 한다.

위험 액션은 실행 전에 영향을 확인할 수 있어야 한다.
특히 진행 기록이 있는 퀴즈의 발행 해제는 기존 진행자의 재도전과 스크립트 열람이 막힌다는 점을 액션 근처에서 다시 보여준다.

## 반응형 기준

관리자 앱은 데스크톱 우선으로 만든다.

넓은 화면에서는 좌측 사이드바, 상단 운영 요약, 목록/상세 2패널을 유지한다.
좁은 화면에서는 목록을 위에 두고 상세를 아래에 두는 단일 컬럼으로 접는다.

모바일 최적화는 v1의 주요 목표가 아니다.
다만 화면이 좁아져도 저장, 발행, 발행 해제 같은 주요 액션과 입력값이 겹치거나 사라지지 않아야 한다.

## 금지 패턴

- 랜딩 페이지형 히어로를 첫 화면으로 만들지 않는다.
- 마케팅 사이트처럼 큰 소개 문구와 장식 이미지를 배치하지 않는다.
- 카드만 과하게 나열해 실제 편집 동선을 흐리지 않는다.
- 주요 입력을 여러 탭 뒤에 숨기지 않는다.
- 단계형 마법사를 기본 편집 흐름으로 쓰지 않는다.
- 발행 해제와 삭제 같은 위험 액션을 저장, 발행과 같은 시각 무게로 두지 않는다.
- 진행 기록이 있는 퀴즈의 잠금 상태를 단순 비활성화만으로 표현하지 않는다.
