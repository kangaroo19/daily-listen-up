# 19. MVP 테스트 시나리오 작성

## 목적

MVP 핵심 플로우가 의도한 정책과 사용자 경험대로 동작하는지 확인할 수 있는 테스트 시나리오를 만든다.

이 작업은 전체 테스트 자동화 체계를 새로 구축하는 작업이 아니라, MVP 완료 판단에 필요한 수동 검증, mock 검증, 실제 WebView 검증 기준을 정리하는 작업이다.

## 구현 범위

- 정상 학습 플로우 테스트 시나리오를 작성한다.
- 오답 후 보상형 광고 기반 재도전 테스트 시나리오를 작성한다.
- 오늘 학습 완료 사용자 재진입 테스트 시나리오를 작성한다.
- 오늘 문제 없음, 문제 조회 실패, 잘못된 문제 데이터 시나리오를 작성한다.
- 로그인 취소, 로그인 실패, 세션 만료 시나리오를 작성한다.
- 오디오 로딩, 오디오 재생 실패 시나리오를 작성한다.
- 선택 전 제출 비활성화, 제출 중 중복 방지 시나리오를 작성한다.
- 전면형 광고 실패와 광고 완료 전 결과 차단 시나리오를 작성한다.
- 정답 포인트 지급 요청 성공, 대기, 실패, 이미 지급 시나리오를 작성한다.
- 보상형 광고 `userEarnedReward` 성공과 `dismissed`만 발생한 시나리오를 구분한다.
- 당일 중복 학습, 중복 제출, 중복 보상 요청 방지 시나리오를 작성한다.
- 각 시나리오에 필요한 테스트 데이터, mock 응답, 실제 기기 검증 필요 여부를 명시한다.

## 제외 범위

- 전체 E2E 자동화 플랫폼 구축
- 운영 모니터링, 분석 이벤트, QA 대시보드 도입
- 서버 내부 정답 검증, 포인트 지급, 멱등 로직 테스트 구현
- 광고 네트워크 자체의 수익 측정 검증
- 비MVP 기능 테스트
- 테스트 결과 completed 문서 작성

## 구현 기준

- 시나리오는 Given, When, Then 또는 같은 수준으로 실행 조건과 기대 결과를 명확히 적는다.
- 정상 플로우는 로그인, 오늘 문제, 오디오, 선택지, 제출, 전면형 광고, 결과, 정답 포인트 지급, 완료까지 포함한다.
- 오답 플로우는 결과 확인 후 보상형 광고, `userEarnedReward`, 재도전, 재제출까지 포함한다.
- 실패 플로우는 실패 후 정답, 보상, 재도전이 낙관적으로 열리지 않는지 확인한다.
- 광고와 프로모션은 로컬 mock 검증과 실제 Apps in Toss 런타임 검증을 구분한다.
- 인앱 광고는 샌드박스에서 테스트 불가할 수 있으므로 QR 또는 실제 토스앱 검증 필요 여부를 표시한다.
- 날짜 기준은 KST `quizDate`를 사용하고, 자정 경계 시나리오를 포함한다.
- 중복 가드는 `409`, `403`, `already_granted`, `already_submitted` 같은 응답 기준으로 검증한다.
- 문제 데이터는 오늘 문제 있음, 오늘 문제 없음, invalid 데이터 상태를 모두 포함한다.
- 테스트 데이터에는 `quizDate`, `audioUrl`, `choices`, `promotionAmount`, 사용자 진행 상태를 포함한다.
- 테스트 시나리오는 구현 코드를 요구하지 않고, 구현된 테스트가 있다면 연결 명령과 범위를 적는다.

## 상태 및 예외 처리

- `authenticated`: 로그인 완료 후 오늘 문제에 진입할 수 있다.
- `unauthenticated`: 로그인 필요 또는 로그인 취소 상태다.
- `empty_today_quiz`: 오늘 문제 데이터가 없다.
- `invalid_quiz`: 문제 데이터 형식이 잘못되었다.
- `submit_error`: 답안 제출 실패 상태다.
- `ad_unsupported`: 광고 API 미지원 상태다.
- `ad_failed`: 광고 로드 또는 표시 실패 상태다.
- `reward_not_earned`: 보상형 광고를 닫았지만 보상 이벤트가 없다.
- `promotion_failed`: 포인트 지급 요청 또는 확인 실패 상태다.
- `completed_blocked`: 완료 사용자가 문제 풀이로 다시 들어가지 못하는 상태다.
- 각 상태별로 사용자가 볼 화면, 활성 CTA, 금지되어야 할 API 호출을 함께 적는다.

## 완료 기준

- 정상 플로우, 오답 재도전 플로우, 완료 재진입 플로우 시나리오가 있다.
- 로그인, 문제 조회, 오디오, 선택, 제출, 광고, 결과, 포인트 지급, 재도전, 완료 상태가 모두 검증 대상에 포함된다.
- 오늘 문제 없음, 조회 실패, 광고 실패, 포인트 지급 실패, 중복 요청 시나리오가 있다.
- 각 시나리오의 테스트 데이터와 mock 응답 조건이 명시되어 있다.
- 로컬 브라우저 검증, mock 검증, Apps in Toss 실제 런타임 검증 항목이 구분된다.
- 광고 미지원 또는 샌드박스 미지원 항목을 실제 실패로 오판하지 않게 기준이 있다.
- 실패 상태에서 결과나 보상이 낙관적으로 열리지 않는지 확인한다.
- 서버 내부 로직 테스트와 운영 QA 체계 구축이 포함되지 않는다.

## Git 전략

- 최신 `dev` 기준에서 `codex/19-mvp-test-scenarios` 형식의 작업 브랜치를 만든다.
- 의미 있는 기능 단위마다 커밋한다.
- 작업 완료 후 같은 번호의 completed 문서를 작성한다.
- 작업 브랜치에서 `dev`로 PR을 보낸다.
- 예외가 필요한 작업은 이 섹션에 예외 사유와 진행 방식을 명시한다.
- 테스트 코드 추가가 필요한 경우 MVP 시나리오 검증에 필요한 최소 범위로 제한하고, 자동화 범위 확대는 별도 작업으로 분리한다.

- 21번 작업은 통과한 시나리오와 남은 실패 항목을 MVP 완료 기준 체크리스트의 근거로 사용한다.
