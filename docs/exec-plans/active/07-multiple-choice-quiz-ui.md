# 7. 객관식 퀴즈 풀이 UI 구현

## 목적

사용자가 오늘 문제의 질문을 읽고 객관식 선택지 중 하나를 명확하게 선택할 수 있게 한다.

이 작업은 답안을 고르는 UI와 선택 상태만 다루며, 제출 API 호출과 정답 여부 확인은 후속 작업에서 구현한다.

## 구현 범위

- 오늘 문제 데이터의 `questionText`를 표시한다.
- 오늘 문제 데이터의 `choices`를 객관식 선택지로 표시한다.
- 사용자가 선택지 중 하나만 선택할 수 있게 한다.
- 선택 전과 선택 후 상태를 시각적으로 구분한다.
- 선택된 `choiceIndex`를 8번 제출 흐름에서 사용할 수 있게 전달한다.
- 선택 전에는 제출 CTA가 활성화되지 않도록 상태 기준을 제공한다.
- 제출 중 또는 화면 전환 중에는 선택지를 잠글 수 있는 기준을 제공한다.
- 모바일 WebView에서 선택지가 터치하기 쉬운 크기와 간격을 갖도록 구성한다.

## 제외 범위

- 오디오 재생 UI 구현 변경
- 답안 제출 API 호출
- 제출 중 서버 응답 처리
- 정답 여부 판단과 결과 표시
- 정답 선택지 강조, 오답 선택지 강조
- 스크립트, 해설, 힌트 노출
- 전면형 광고, 보상형 광고 호출
- 포인트 지급 요청과 지급 결과 표시
- 복수 선택, 주관식 입력, 타이머, 난이도 선택
- completed 문서 작성

## 구현 기준

- 4번 작업에서 정의한 `questionText`와 `choices`만 입력으로 사용한다.
- 객관식 UI에는 `correctChoiceIndex`와 `script`를 전달하지 않는다.
- 클라이언트는 선택 시점에 정답 여부를 계산하거나 표시하지 않는다.
- 선택지는 원본 배열 순서를 유지한다.
- 선택 상태는 `selectedChoiceIndex: number | null` 형태로 관리한다.
- 선택지는 하나만 선택할 수 있고, 새 선택지를 누르면 이전 선택은 해제된다.
- 같은 선택지를 다시 눌렀을 때 선택을 유지할지 해제할지는 UX 기준을 명확히 정하고 일관되게 처리한다.
- MVP에서는 선택 해제보다 다른 선택지로 변경하는 흐름을 우선한다.
- 선택지 컴포넌트는 TDS 리스트, 버튼, 카드형 선택 UI를 우선 검토한다.
- 하단 제출 CTA는 TDS `Button` 또는 Bottom CTA 패턴을 우선 사용한다.
- TDS `Button`을 사용할 때 주요 제출 액션은 `display="full"` 기준으로 배치한다.
- 선택 전 제출 CTA는 `disabled` 상태로 표시한다.
- 선택지가 잠긴 상태에서는 사용자가 선택을 바꿀 수 없게 한다.
- 선택지는 충분한 터치 영역을 가져야 하고, 선택됨 상태가 색상만으로 전달되지 않게 한다.
- 질문과 선택지는 위에서 아래로 자연스럽게 읽히도록 배치한다.
- 보상 금액, 정답 여부, 결과 안내 문구를 선택 UI 안에 섞지 않는다.
- 선택지 데이터가 잘못된 경우 문제 풀이를 계속 진행하지 않고 오류 상태로 전환한다.

## 상태 및 예외 처리

- `loading`: 문제 데이터가 아직 준비되지 않았다.
- `ready`: 질문과 선택지가 표시되고 선택할 수 있다.
- `no_selection`: 아직 선택한 답안이 없어 제출할 수 없다.
- `selected`: 하나의 선택지가 선택되어 제출 가능 상태다.
- `disabled`: 제출 중이거나 화면 전환 중이어서 선택지를 바꿀 수 없다.
- `invalid_choices`: 선택지가 없거나 2개 미만이어서 퀴즈를 진행할 수 없다.
- `error`: 질문 또는 선택지 데이터 형식이 잘못되었다.
- 선택지가 비어 있으면 빈 선택지 목록을 보여주지 않는다.
- 선택지 텍스트가 길어도 버튼이나 행 밖으로 넘치지 않게 줄바꿈한다.
- 빠른 연속 탭에도 최종 선택 상태가 하나로 유지되어야 한다.
- 문제 데이터가 바뀌면 이전 선택 상태를 초기화한다.
- 사용자가 페이지를 재진입하면 서버 또는 진행 상태 기준에 맞는 초기 선택 상태를 사용한다.

## 완료 기준

- 사용자는 질문과 선택지를 한 화면에서 명확히 구분할 수 있다.
- 선택지 중 하나만 선택할 수 있다.
- 선택하지 않은 상태에서는 제출 CTA가 활성화되지 않는다.
- 선택된 `choiceIndex`가 8번 제출 흐름으로 전달될 수 있다.
- 제출 중 또는 비활성 상태에서는 선택지가 잠긴다.
- `correctChoiceIndex`와 `script`가 UI, 상태, 로그에 노출되지 않는다.
- 정답, 오답, 해설, 결과, 광고, 보상 흐름이 포함되지 않는다.
- 모바일 WebView에서 선택지와 하단 CTA가 겹치지 않는다.
- TDS 우선 기준과 짧고 직접적인 문구 기준을 따른다.
